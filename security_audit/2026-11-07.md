This is a point-in-time review of the flaggator process and the operator console. No application code was changed. The 2026-10-31 record in `docs/security_audit.md` was left as it stands; the fixes recorded there (F1–F13) were read again and still hold.

## Method

Static read of `src/` and `ui/` against `docs/security.md`. Routes, authentication, authorization, SQL, token handling, the public evaluation path, the WSGI adapter, and the console pages were included. No exploit was run against a live server. Ratings assume the deployment described in `docs/security.md`: one process, default bind `127.0.0.1`, and a reverse proxy with TLS when the service is reachable beyond loopback.

Severity:

| Severity | Meaning |
| --- | --- |
| Critical | Unauthenticated remote compromise of credentials or flag configuration, with a direct path in this tree. |
| High | Authenticated compromise, or a reliable unauthenticated leak or takeover, that the current controls do not contain. |
| Medium | A real break of a stated control, usually under a deployment the project already documents (reverse proxy, MySQL, or an external IdP). |
| Low | A narrower exposure, a race, or a missing browser control. The server-side authorization check still holds. |

Grok 4.7 Extra High identified no Critical or High issue in this commit. Claude Opus 5.5 rated SA-11 High.

## Notes for the next pass

SA-1 through SA-4 are the ones that change who can sign in, who a JWT belongs to, or whether secrets stay on the host. SA-5 through SA-10 are smaller, and SA-8 matches a rule the security document already states.

SA-1 is availability. Counting every caller as the proxy address makes the limit a switch an outsider can hold down. Keeping the proxy address as the only input also means the limit cannot tell operators apart from the outsider.

SA-2 is the gap in credential rotation. Changing the password replaces the hash and leaves every already issued HS256 token working. A short fixed lifetime contains a stolen token; an unbounded lifetime does not.

SA-3 is conditional on an external IdP. The signature, issuer, audience, and expiry checks are in place. The missing check is that the address in the token was verified by that IdP.

SA-4 is conditional on a MySQL host that is not local. The password is omitted from `MysqlDatabase`'s `repr`. The bytes on the wire are not protected, and the code offers no switch for TLS.

## Checked and still sound

Recorded so the next pass does not reopen them without a code change.

- F1–F13 from the 2026-10-31 audit remain closed: the body size is rejected before `read`, the server caps in-flight requests and sets a socket timeout, JWKS fetches time out, login burns scrypt on a miss and answers 401 for a bad password shape, a non-empty JWT secret must be at least 32 bytes, an IdP token does not select a user by a numeric `sub`, granting `protected_writer` requires that role, SQLite files are mode `0600` after connect, cache fills check a generation counter, and the flag, segment, clause, and context caps are enforced.
- Repository SQL binds values. The audit list builds `WHERE` from constant fragments and binds the caller's keys. `LIKE` searches escape `%`, `_`, and the escape character.
- The evaluator does not call `eval`, `exec`, or the shell. Clause operators are a closed set. There is no regular-expression operator.
- Prerequisite cycles are rejected on write. Evaluation stops at depth 10.
- An SDK token is confined to its environment. A user JWT cannot call evaluate, evaluate-all, or evaluation-config. Opaque management tokens carry every management role.
- Roles used for authorization are loaded from the enabled local user row. The `roles` claim inside the access token is ignored by the API. The console reads that claim to show or hide management controls (`ui/roles.js`, `ui/projects.js`, `ui/users.js`); a stale claim changes the screen, and the API still returns 403.
- JWT verification pins the algorithm. `none` is rejected. HS256 is checked with the local secret. RS* and ES* are checked with the configured JWKS. The two keys are not interchangeable.
- Password hashes and token secrets are absent from API responses and from audit JSON. Opaque token lookup compares hashes with `hmac.compare_digest`.
- Console paths reject empty segments, `.`, `..`, a null byte, a backslash, and a symlink that resolves outside `ui/`.
- API errors returned to the client do not include driver text. Unhandled exceptions become a generic 500.
- The console sends the access token in the `Authorization` header from `sessionStorage`. It is not a cookie, so a cross-site form post does not carry it. Cross-origin reads are not enabled: responses set no CORS headers.
- Public keys are a closed pattern, so a path segment cannot escape into another resource.
- The evaluation cache stores bundles, not bearer tokens and not request contexts. A fill that started before an invalidation does not write back over the delete.

## Out of scope

A running process was not attacked. Dependency advisories for `PyJWT` and `cryptography` were not re-checked against a live index. The host, the reverse proxy, and the MySQL account privileges sit outside this tree.
